Questions Regarding Sakai

Sakai is the previous learning platform used by URI. It has been replaced by Brightspace since roughly 2020. As a result, all data stored on Sakai has been deleted and can't be recovered. If a user contacts us with questions regarding Sakai, we are unable to recover any information for them, including course work, syllabi, etc. If the user is looking for a syllabus, the most we can do to help is provide them publicly available contact information for the professor (if the user remembers the professor's name). They can also try to look for their professors name under the academic records tab.

Error Code: MissingKeyMissing Key-Pair-Id query parameter or cookie value

Indicates that cookies are not enabled in your web browser for the Pulse App's particular website. Once cookies are enabled, this error will disappear and you will be able to access the content. 

For Safari users on iOS 11: Both the Block All Cookies and Prevent Cross-Site Tracking settings must be disabled under Safari's Privacy & Security Settings. You can re-enable Prevent Cross-Site Tracking once you've accessed the content for the first time.

For all other Safari users: Note that you will need to change your cookie settings to Always allow to initially access the content. Once you access for the first time, you can change your cookie settings back to the previous setting with the exception of Always block.

For Chrome users on iOS 11: Chrome for iOS does not provide advanced settings to adjust cookies. Safari is recommended as an alternative.

Alias Admin Accounts for Brightspace

If a user comes in with a Brightspace issue related to logging in AND you see that they have an account in Azure that starts with LTD (example: "ltd_kevingray@uri.edu"), then it's an indicator that it is an admin account for Brightspace. Those accounts specifically in Azure are basically alias admin accounts for Brightspace—if someone ever calls to have the password reset for it, it's a quick ticket to security. Security will send the user a secure email to get their new temporary password.

Certain roles in Brightspace are automatically populated through e-campus, these roles cannot be changed in Brightspace and need to come through e-campus. These roles are as follows: Lecturer, Learner, Administrator of Record.

Course Merge

There are two ways to merge courses: the self merge form and the administrative course merge. 

The self merge form should be used anytime they are merging courses where one individual is the instructor or administrator on record privileges/role assigned to the courses to be merged. Basically, most courses fall into this catagory, and as long as the course sections are taught by the same professor, self-merge applies. 

The administrative course merge is only for "difficult" course merge situations, or when there are different instructors or administrators on record assigned to the courses to be merged. For courses cross-listed and/or taught by multiple professors, this is the required method. It is important to note that The only classes that can be merged are those taught by the same professor(s). Two professors cannot merge two different courses in which they are not both on all those courses in eCampus. Faculty are allowed to co-teach, so the method approved by the Provost's office at this time is that those co-teaching faculty need to ask their chair to add them both to all ecampus sections they will co-teach (as the primary and secondary professors in each ecampus section). Once they are both listed on all of the sections they will co-teach then they will both sync into all the course shells in Brightspace together automatically. After that they will be able to merge the sections.

It is only used for very few rare cases and situations in which the professors cannot merge themselves. That does not include co-teaching since they can have their chair add them to all sections in ecampus and then they can merge. There are some biology courses in which some unique things are done with the TAs and how they are arranged between sections that we do for them, and a few other rare cases. In those cases, they must submit a ticket, and once the ticket is submitted they can be given a google form to fill out and then ITS Teaching and Learning would do the manual merge for them. So the form is used for classes that use TAs as instructors. This is a special case.

It is important to note that only the content for the destination course is kept. The content from sites being merged into the destination will not be kept. As of right now (1/18/24) courses that are merged are not able to have their name changed whatsoever. A temporary solution would be to change the header inside the top-parent course shell they merged under to add all the section numbers and email all the students to let them know what the top shell # is.

Course Site

Course Shells will appear for the instructor in Brightspace about 60 days before the start of the academic term. They will automatically be created and appear for the primary instructor of the course listed in e-campus.

Course sites cannot be deleted but an instructor can request to have the course reset if they want to start over from scratch with an empty course shell (for a current semester). Old course sites from previous semesters cannot be reset.

Instructors Adding Students to Official Course Sites

The feed between e-Campus and Brightspace is not 100% reliable, so (some) students that should appear in the official Brightspace course do not show up in the Brightspace Classlist. Ask when the student enrolled in the course and if it was not within the last 24 hours check to see if the student has done/can do the following:

  1. Contacted a peer student in the class to see if they can see the course

  2. Contacted the professor to verify that it's been activated 

  3. If so, ask the professor to look through the Classlist in Brightspace and see if they can see the student's name there

  4. If not, have the professor temporarily add the student as an Incomplete Student to the course

If the student should be able to see the course after checking but still cannot, create a ticket for the student, and include: 

  • Course name from e-Campus 

  • The professor's name, 

  • When they enrolled in the course 

  • Contact phone number.

 Classify the ticket as Brightspace --> Student issue with Access and assign it to ITS Admin Applications so that the student's role can be converted from Incomplete Student to Learner

Enrolling TA/TA Plus

If course instructors want TA/TA Plus to be part of an official URI course in Brightspace, the TA and TA Plus CANNOT be enrolled in the course through e-Campus. They have to be manually added to the official course site by the course instructor. 

Enrolling GTA

Grad TAs cannot be added by an instructor. The department sends a list to enrollment services and then enrollment services enrolls them in e-campus as a second instructor as someone in the class.  

Project Site

Project sites are created manually and is located at the bottom right corner of the home page. 

Project sites can be self reset/recycled/deleted via Course Tools → Course Admin → Course Reset → Select boxes for “Choose components to Permanently Delete” → Copy and Paste the Course Code. To change the name of project site: Course Tools → Course Admin → Course Offering Information → Edit “Course Offering Name”

To delete the project site entirely, a ticket needs to be submitted to the T&L team. However, only the Project Site Owner can request to delete the project site.

Oops, your file could not be uploaded

For students who receive the "Oops, your file could not be uploaded" error message on Brightspace when trying to submit a file in Assignments, Quizzes or Discussions, the typical cause is their filename. Brightspace has a set of illegal characters (\ / : * ? " < > | ~ # % & + { }) and if any are present in the filename, people will get that error message. Remove them and have the user submit the file again.
